# Borderly Data

Репозиторий удалённых визовых данных для Android-приложения Borderly. Текущий
контракт: schema v1, taxonomy v1, provenance v1, visa data v14.

## Что публикуется

- `visa_requirements.json` — 199 паспортов × 248 направлений; в каждой строке
  ровно 247 правил без страны самого паспорта.
- `visa_status_taxonomy.json` — единственная взаимоисключающая классификация
  визовых статусов.
- `passport_index_source.json` — канонический снимок основного источника,
  хеш и размер которого закреплены в базе и `version.json`.
- `sources` и `provenance` внутри визовой базы — реестр происхождения каждого
  правила: отдельный официальный источник, общий набор данных или производное
  территориальное правило.
- `entry_requirements.json` — только невизовые формальности: arrival card,
  предварительная регистрация, декларации и аналогичные требования.
- `entry_guides.json` — проверенные инструкции и официальные ссылки для
  отдельных связок.
- `version.json`, `entry_requirements_version.json`,
  `entry_guides_version.json` — манифесты неизменяемых релизов из `releases/`.

Приложение принимает новый файл только после проверки версии схемы, имени
неизменяемого релиза, размера, SHA-256, числа записей и полной структуры JSON.
Повреждённое или несовместимое обновление не заменяет последнюю рабочую базу.

## Канонические визовые категории

В `visa_requirements.json` разрешены только:

1. `freedom` — свобода передвижения;
2. `visa free` — без визы;
3. `eta` — eTA/ESTA и аналогичное разрешение до поездки;
4. `visa on arrival` — виза по прибытии;
5. `e-visa` — электронная виза;
6. `visa required` — нужна предварительная виза;
7. `entry restricted` — обычный туристический въезд ограничен;
8. `special permit` — требуется специальное разрешение;
9. `mixed requirements` — правило зависит от территории, документа или
   маршрута и не сводится к одной обычной категории.

Arrival card никогда не является `eta`: такие формальности допускаются только
в `entry_requirements.json`. Рейтинг получает балл только за `freedom` и
`visa free`.

## Автоматическое обновление

Workflow `.github/workflows/update-visa-data.yml` запускается ежедневно и:

1. загружает основной Passport Index и расширенный сравнительный снимок;
2. проверяет официальные политики, ограничения, специальные режимы и
   Гренландию;
3. синхронизирует каждое обычное core-правило с Passport Index 1:1, включая
   смену категории и срок пребывания;
4. применяет поверх снимка только полные официальные правила из явных
   policy/watch-реестров;
5. проверяет, что все 38 418 неофициальных core-правил точно совпадают со
   снимком, а 984 официальных исключения имеют источник и дату проверки;
6. оставляет arrival card и другие декларации только в
   `entry_requirements.json`, где они не могут изменить статус на карте;
7. прогоняет полный `node validate_all.mjs`;
8. создаёт новый неизменяемый релиз, хеш и манифест и публикует его только при
   успешном прохождении всех защит.

Защита от массовой поломки источника остаётся: слишком большой или
аномально распределённый пакет изменений останавливает публикацию. Карантин
теперь относится к замороженным non-core направлениям и изменениям, которым
нужен отдельный аудит, а не к штатной смене категории Passport Index.

## Проверка перед публикацией

```bash
node validate_all.mjs
```

Проверка должна завершиться строкой `All Borderly data checks passed`.
Предупреждения не скрываются: сейчас 25 non-core территорий заморожены до
отдельного официального аудита. Поэтому core-матрица строго совпадает с
зафиксированным источником с официальными исключениями, но вся расширенная
матрица не называется официально сертифицированной для всех 49 153 связок.

Ручное изменение `version.json` без создания соответствующего файла в
`releases/` запрещено. Для штатного выпуска используйте updater и затем
`validate_all.mjs`.

## Источники и лицензия

В v14 происхождение указано для всех 49 153 правил: 3 706 записей имеют
отдельный официальный источник, 43 289 ссылаются на общий набор данных, а
2 158 помечены как производные территориальные правила. Основной источник —
`imorte/passport-index-data`; приоритетные исключения
проверяются по официальным страницам из policy/watch-реестров. Ежедневный
workflow не заявляет мониторинг всех государственных сайтов мира: автоматически
проверяются только зарегистрированные официальные политики и наблюдения.

лицензированным источником. Полная атрибуция: `DATA_ATTRIBUTION.md`.
